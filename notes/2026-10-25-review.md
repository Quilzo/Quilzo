## What was fixed 

### The split [#351]
Quilzo still carried every package Vaigil had taken: collection, detections and Sigma, correlation, the finding queue, cases and incidents, automations, vulnerability management, estate and workforce, vendors, reviews, reminders, work tracking and estate canaries, with their commands, screens, MCP tools, help, privilege rows and docs. About 95,000 lines left. What Quilzo needs to defend itself stays, rewired where it leaned on what left: 
- **Risky sign-ins confirm it is them**, built in and on (`signin.adaptive`, NIST SP 800-53 IA-10): impossible travel, a moved session, Tor or a hosting provider, an administrator in a new country, or high risk holds the session until a passkey confirms it. Before, this was automation rules nobody had until they added them. 
- **Shield** notifies by mail directly (new `internal/mail`: STARTTLS required, one recipient, header-injection checks), in the background. "Open a case" becomes an audit record (`shield.open-case`) for the SIEM. 
- **Posture drift** goes to the audit log (`posture.drifted`, `posture.restored`); high and critical are mailed. 
- **selfvuln** reads its own OSV records, and `quilzo self kev FILE` loads CISA's exploited catalogue. 
- The menu's *Security operations* becomes *Protection* (Shield, Sign-ins). 

### Security bugs [#351]
| Bug | Cause | Fix |
|---|---|---|
| A sandboxed program could reach the network while its network was denied | Landlock's TCP rules do not cover MPTCP sockets (Linux 6.18), and Go opens listeners as MPTCP by default since 1.24. `listen()` on an unbound socket also bound a port without Landlock asking. | The seccomp filter answers MPTCP with EPROTONOSUPPORT (Go and libc fall back to TCP) and refuses `listen`. Extensions now get the network part of the filter. `internal/sandbox` |
| Admin actions missing from the audit log | Records took their principal from `detail["by"]`. Publishing from the browser, notes, media edits, token exchange and policy enforcement set none, so the log refused them (AU-3). So did refusals at the door, with nobody signed in. | Each names its actor. Door refusals are kept as anonymous and unverified, and failures are recorded as failures. A source-walking test guards it. |
| A new store could not issue its first token | `token issue` waited for a second administrator who could not exist. | The sole administrator's bootstrap token is their own change, recorded as `dual.approved bootstrap=true`. |
| `auth grant` said "can now: nothing" for every grant | It read the policy as it was before the grant. | It reads the policy the grant produced. |

### Found by using it [#351, #352]
A Chromium crawl of every admin screen (792 visits), signed in with a real passkey through a virtual authenticator, at 1280 and 390 pixels. An MCP client driving all 48 operations over stdio. All 411 commands run once each. 
- **Publishing over MCP had no boundary.** `quilzo_write` says "Never publishes", yet `publish` was one of its operations. A host that asked a person whether an agent might draft was also asking whether it might go live. Publishing is now `quilzo_publish`, marked destructive and open world. The two tools refuse each other's operations. 
- **19 commands ignored `--json`** and printed prose, among them `token list`, `auth list`, `secret list`, `apps list` and `version`. Each now writes one document, with no token hashes or secret values. A test runs all 19 as a subprocess. 
- Getting started's "Publish it" linked to POST-only `/publish` (405). It opens Review. 
- The Passkeys table scrolled the phone screen 106px sideways, and Inventory did the same by 6px. A test now fails on any table outside a scrolling frame. 
- Images opened on their own were refused every style Chrome gives an image document. Inline media gets its own policy: the browser's styles, sandboxed, nothing that runs. 

### CodeQL, without dismissing anything [#351]
The required CodeQL check failed #351 on eight alerts that main carried unchanged. Running CodeQL 2.27.3 locally on main and on the branch gave the same 22 alerts with the same fingerprints. The diff was too large for GitHub to tell which lines it changed. Instead of dismissing them: 
- A model pack, `.github/codeql/extensions/quilzo-go`, states the escaping CodeQL cannot read. `tmpl.Render` autoescapes as `html/template` does, and a SCIM reply is JSON under `nosniff`. The workflow passes it with `CODEQL_ACTION_EXTRA_OPTIONS`. 
- Three code edits let CodeQL follow the rest. The preview bar's escapers are named functions, its links are escaped for the attribute as well as the URL, and `behindTLSProxy` has no constant `false`. 
- Result: `security-extended` reports one alert, the studio's loopback-only cookie, already recorded as won't-fix. Each claim and what would make it wrong is in `docs/codeql-dismissals.md`.

### How it defends itself 

Shield playbooks with a record of how often each was right, smart lockout, decoys, adaptive sign-in with step-up, two-administrator control for privileged changes, posture rules with drift on the record, self-verification of its own binary, OSV records and CISA KEV. 

### Isolation 

Extensions and agent programs run under Landlock and a hand-written seccomp filter, now closed against the MPTCP and `listen()` bypass. The admin binds to loopback by default, sends a strict CSP (no script) and refuses cross-site posts. One gap remains: the internet-facing public site server is not confined. See finding 2. 

## Open findings, ranked 

### 1. The model-usage ledger drops write failures, and model calls are not in the audit log [Decide, then fix]
`internal/gateway/gateway.go`, `Ledger.record` and `OpenLedger` 

If `model-usage.jsonl` cannot be written (disk full, permissions), the in-memory totals still go up, but nothing persists and nobody is told. After a restart every daily and monthly budget refills, which is OWASP LLM10, unbounded consumption. Model calls also never reach the signed audit log or the SIEM stream, so an LLM call is the one actor in the table above that a receiver cannot see. 

**Proposed:** keep the ledger's last write error and expose it; have the budget check refuse budgeted callers while the ledger cannot write (fail closed, as the audit log does), with a posture rule that says so. Also write a `model.call` audit record per call: consumer, route, model, token counts, cost and outcome, never content. That needs a decision on volume: per call, or one summary record per consumer per minute. 

### 2. The public site server is not confined [Fix]
`cmd/quilzo`, the `quilzo site` command 

The internet-facing server runs as the same user with access to the whole store. It could write `policy.json` and `tokens.json` if it were compromised. The docs still say it has "exactly one write capability", which is no longer true. 

**Proposed:** re-exec `quilzo site` through the existing sandbox shim (`RestrictAndExec`) with read access to published content and write access only to the directories it needs (form submissions and wholesale enquiries), then correct the docs. The sandbox tests already show how to assert what a confined process can and cannot open. 

### 3. Agents' MCP programs that name `quilzo_write` for publish must move [Communicate]
Since #352, a hard-coded program that calls `quilzo_write{operation:"publish"}` gets a refusal naming `quilzo_publish`. LLM agents find the right tool through `quilzo_find`. NEWS says so; worth one line in the release notes. 

### 4. MCP protocol version [Improve]
Asked for `2025-11-25`, the server answers `2025-06-18`. The spec allows that, but newer clients will negotiate down. Read the November 2025 changelog and adopt what fits: client ID metadata documents for registration, tool icons and titles, and tasks for long operations such as publish. 

### 5. First-run friction [Improve]
- After enrolling a passkey from an enrolment link, the person has to sign in again. The enrolment could end in a signed-in session. 
- A fresh store scores 16 out of 100 on posture, with a critical finding for the bootstrap admin token. That is correct, but it reads as alarming on the first screen. Say what to do next instead. 
- `quilzo agent probe` waits on standard input with no hint that it is waiting. 
- The studio cookie (CodeQL #59) can become `Secure` unconditionally once Safari accepts Secure cookies on `http://localhost`.

## Vaigil: receiving Quilzo's audit stream 

The decision was that Quilzo streams its audit log and Vaigil reads it, with a Quilzo source and `quilzo.*` rules. Quilzo's side is done (#348, #351). Vaigil's side is designed but not written. 

### What Vaigil already has 
- `internal/auditstream.Receiver`: verifies the RFC 9421 signature and content digest, chain continuity (409 with `{"holds": N}` on a gap), and that the leaves rebuild the signed tree head. 
- `audit.NewHeadVerifierIn("quilzo/audit-head/v1", ed, ml)`, which verifies heads in Quilzo's signing context. It is already allowed by `name_test.go`. 
- A feed pipeline in `cmd/vaigil/inboundserve.go`: verify, `accept`, map, spool, rules, automations. Feed kinds are `okta`, `webhook`, `github` and `ssf`. 
- `vaigil.*` rules over its own log (`vaigil/audit`), originally Quilzo's self-rules, matching `raw.action`, `raw.role` and `raw.outcome`. 

### What to build 
1. **A `quilzo` feed kind** in `internal/inbound`. It pins the output of `quilzo siem stream key --json`: `key_id`, `public_key`, `head_key_id`, `head_ed25519` and `head_mldsa`. Added with `vaigil inbound add quilzo NAME --keys FILE`, in `makeFeed` and `inboundAdd`. 
2. **The endpoint**: `case inbound.Quilzo` in `ServeHTTP`, POST only, with a body limit of about 8 MiB (500 records per batch). A cached `auditstream.Receiver` per feed, restored from `inbound/NAME.leaves` (one hex leaf per line). `Accept` the batch, then persist the leaves and answer `200 {"holds": To}`. Answer a gap with 409 and `{"holds": N}`. Answer anything else with 401 and a bare body, putting the reason in the audit log via `s.refused`. 
3. **The mapping**: each OCSF line becomes a `telemetry.Event` with source `quilzo/audit`. Class 3002 maps to Authentication and the rest to API Activity, and `status` to the disposition. The actor is `{issuer: "quilzo", value: actor.user.name}`, and raw is `action = api.operation`, `outcome`, `resource = resources[0].uid`, `kind` from `actor.user.type` (User, Service, AI), plus an allowlist of `unmapped.detail_*` keys: role, alone, kind (as `request_kind`), severity, signal, playbook, title, rule, failures and setting. Add an `events` field to `pushed` so `store()` appends them directly. 
4. **The rules**, in `internal/detect/pack/quilzo.*.json`, each with a matching and a non-matching fixture: `admin-granted` (auth.granted, access.grant or scim.granted with role admin), `admin-token-issued`, `audit-log-moved` (`auditlog.dir`), `break-glass` (`auth.break-glass`), `privileged-change-alone` (`dual.approved` with `alone=true`), `signin-failures` (`auth.failures`), `account-locked`, `decoy-touched` (`shield.decoy-touched`, high severity), `shield-asked-for-a-case` (`shield.open-case`), `posture-drifted` (`posture.drifted` with severity high or critical) and `risky-signin` (`signin.signal`). 
5. **The name test**: allow the files whose job is Quilzo's stream (`internal/inbound/quilzo.go`, the feed handler, `pack/quilzo.*.json`). The test's own rule is that Quilzo may be named "only where Vaigil means Quilzo", and this is that case. 
6. **Tests against real batches.** A copy of a Quilzo store had `siem.stream.url` pointed at a local capture server. `quilzo siem stream send` then produced batch 1 (records 1 to 43) and, after an admin grant and a token request, batch 2 (44 to 46). Keep them in `cmd/vaigil/testdata/quilzo-stream/` with the keys JSON, and replay them with `s.now` set to the signature's creation time. Assert: batch 1 returns holds 43, and its events are in the spool as `quilzo/audit`. Batch 2 returns holds 46, and `quilzo.admin-granted` and `quilzo.privileged-change-alone` fire. Replaying batch 1 gives 409 with holds 46, batch 2 sent first gives 409 with holds 0, and a changed byte gives 401. The capture was in session scratch space, which does not persist, so regenerate it with the steps in section 8. 

## Research and roadmap 

These are measured against the current standards, as far as I know them as of mid-2026. Check each spec's latest revision before building. 

| Area | Where Quilzo is | What to do next |
|---|---|---|
| Authentication (NIST SP 800-63B-4) | Passkeys, AAL2 on every request, idle limit of an hour and 15 minutes for anyone who can grant, smart lockout | Offer phishing-resistant authentication first and treat the API token sign-in as recovery only. Count synced passkeys and device-bound keys separately in posture, since the Passkeys screen already tells them apart. |
| Passkeys (WebAuthn Level 3) | Registration and sign-in, with hardware keys identified | Conditional mediation (passkey autofill on the sign-in field). The Signal API, so a removed passkey disappears from the person's password manager. A conditional create that upgrades a token sign-in to a passkey without a separate screen. |
| OIDC and OAuth for MCP apps | PKCE, refresh rotation with reuse detection, consent with a passkey or SSO behind it, `max_age` and `amr` checks | Check exact redirect matching and the RFC 9700 security BCP item by item. Publish RFC 9728 protected resource metadata, if not already, for MCP clients. Consider DPoP (RFC 9449) for refresh tokens held by desktop agents. |
| SAML | A hand-written XML-DSig verifier with captured fixtures | Add a fuzz test and a signature-wrapping corpus (assertion moved, duplicated IDs, comments inside NameID). The verifier is a component where one parser difference is a full bypass. |
| Agents (OWASP Top 10 for LLM Applications, 2025) | Manifests, egress allowlists, human approval, sandboxed programs, AgentDojo 26/26 refused | Fix finding 1 (unbounded consumption). Add a tool-poisoning check for MCP servers offered through the gateway: the tool-change pinning exists, so surface a changed tool description as a held approval rather than a log line. |
| CMS | Content gates (accessibility, provenance, brand claims, rights), draft and live refs, rollback | Scheduled publishing exists, so add a preview link for a scheduled change that a reviewer without an account can open once, signed and expiring. |
| UX | Getting started, Today, Protection; no script in the admin | Run the passkey crawl from this session in CI (a Playwright job) so phone-width overflow and dead links fail a pull request. Fix finding 5. |

## Architecture verdict 

**Keep it.** One Go binary with only the standard library, one store, and every surface (browser, CLI, MCP) going through the same gates. This is the main reason the project can make strong claims and test them. The split leaves Quilzo with a coherent job: run content and agents safely, defend itself, and hand its evidence to whoever watches. 

Two structural changes are worth making: 
1. **Privilege-separate the processes**, starting with the public site (finding 2). The admin, the site and agent programs should not share one set of file permissions. 
2. **One evidence path.** Everything that acts, model calls included, should reach the signed audit log, so the stream to Vaigil is complete by construction (finding 1).
