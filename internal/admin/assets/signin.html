Create one with quilzo auth grant you admin, then quilzo token issue you --principal you --role admin. Both: the grant is what gives you a role, the token is how you prove you are you, and a token on its own signs in and is then refused by every screen.

Submitted as a POST, so the token never reaches the address bar, the browser’s history, or a server log.

Why there is no password

Because then there is no password store to leak, no reset flow to subvert, and nothing for credential stuffing to stuff. A token is generated, shown once, and stored only as a hash.

There is also no puzzle. WCAG 2.2 treats image recognition and transcription as cognitive function tests and prohibits relying on them, and pasting a string is something every person and every password manager can already do.

What this is

  • Content addressed by the hash of its own bytes, so history is free and rollback is a pointer move.
  • Nothing executes: no plugin runtime, no scripting in templates, no expressions in queries, no JavaScript in this interface.
  • No third-party dependencies at all, in an image built from scratch with no shell, no package manager and no libc in it.

Repeated failures here are slowed rather than locked out — a hard lockout is a denial of service somebody aims at you by failing your logins for you.
